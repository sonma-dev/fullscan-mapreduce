# 8. Architecture Decision Register

## How to Use This Document

This register consolidates unresolved requirements in the seven supplied Markdown specifications. It does not amend those specifications or record new architectural approvals.

Only `01_screen_functions.md`–`07_processing_flows.md` were reviewed. Quotations below are from those Markdown specifications; no original PDF, Map evidence, or other source context was inspected.

### Status and implementation rules

- **TBD:** Necessary definitions or evidence are absent.
- **Needs confirmation:** A choice, predicate, boundary, or conflicting statement requires explicit confirmation.
- **Unadopted proposal:** An option is expressly permitted or illustrative but has not been selected.
- **Resolved:** Explicit, consistent confirmed statements answer the stated question. Resolution applies only to that question, not to adjacent missing details.

An implementation AI may follow confirmed constraints while keeping dependent work on hold. It must not select an unresolved technology, role grant, numerical value, formula, schedule, design option, or recovery behavior independently.

No decision maker, approval date, or calendar deadline is assigned here. References to implementation lock or enterprise general availability preserve prerequisite milestones, not invented dates.
